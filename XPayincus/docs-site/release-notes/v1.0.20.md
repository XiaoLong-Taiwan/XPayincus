# v1.0.20 Agent WSS 管理隧道與宿主資訊修復

本版為發行目標，正式發布狀態以 GitHub Release 為準。三份 VERSION、四份 package.json、Go Agent 預設版本、RFW 三個自家 crate 與 Cargo.lock、Compose 標籤、版本 fixture 及現行文件同步至 v1.0.20。

## WSS 管理與協調升級

- Agent 主動建立 `wss://<Panel origin>/api/agent/tunnel`，重用 HMAC 認證並綁定宿主。面板經隧道存取 Incus Unix socket `/var/lib/incus/unix.socket` 與 Caddy `127.0.0.1:2019`，不直連宿主 Incus／Caddy 管理埠，斷線時不回退至遠端直連。
- 終端、檔案、備份匯出／還原及搬遷經受限的 WebSocket／HTTP 串流轉送，採分塊 ACK、credit 與有界 buffer。斷線、逾時或取消可能造成寫入結果未知，須查詢 operation 或實際資源狀態，不自動重播寫入，也不跨重連續傳。
- Server 與 Agent 須協調升級至支援相同 `http-*`／`ws-ack` frame 的版本；沒有舊 Agent 能力協商或自動降級。安排管理維護時段完成雙端更新，確認心跳、WSS 隧道及實際管理操作後恢復作業。最低 updater `v1.0.3` 是更新器門檻，不代表舊 Agent 相容新隧道。
- 面板須提供有效 HTTPS 憑證，反向代理須允許 `/api/agent/tunnel` 的 WebSocket Upgrade 與長連線；Agent 須有 Incus socket 權限。隧道 registry 維持單一 Node 程序限制。完整協定與容量限制見 [TUNNEL.md](../../../XPayincus-Agent/TUNNEL.md)。

## 容量、架構與端口

- Agent 回報 Incus 儲存池的實際 total／used；面板以已關聯用途為 `instance_data` 的系統盤儲存池容量換算 GiB，修正以宿主根目錄容量代替系統盤容量的問題。CPU、記憶體及儲存容量只在原設定為零且有有效回報時自動補入，保留管理者既有配置；缺失資訊不冒充有效容量。
- 心跳回報宿主 CPU 架構，將 `amd64`／`x86_64`／`x64` 正規化為 `x86_64`，`arm64`／`aarch64` 正規化為 `aarch64`；無效值不覆蓋已知架構，避免宿主與映像架構判斷錯誤。
- 管理端端口頁列出資料庫受管 NAT 映射，按協定與公開端口匹配 Incus proxy device，顯示 IPv4／IPv6、實例類型及系統管理標記。離線或讀取失敗顯示 partial／unknown；範圍僅為受管映射，並非宿主全部 listener 或防火牆掃描。

## Caddy 遷移與恢復

- Caddy 接受既有 `admin localhost:2019`，將 Caddyfile 與 autosave 的 admin 位址遷移至固定 `127.0.0.1:2019`。autosave 只改 admin listen，保留站點與其餘設定。
- 停止服務後備份原始設定及 autosave，驗證暫存設定後原子切換；啟動後檢查服務、listener、程序擁有者及 API 設定是否與預期一致。
- 驗證或切換失敗時恢復原始設定、autosave 與啟用／執行狀態；備份保留於權限 0700 的目錄。恢復失敗明確報錯，不宣告成功。自訂設定路徑或啟動命令需人工處理。
- 新增 localhost 相容、站點保留、不安全 admin 拒絕及失敗恢復案例。

最低 updater 維持 `v1.0.3`，發行契約維持 30 件資產及 16 筆 SHA256SUMS；保留歷史紀錄、第三方依賴及宿主資產釘選。
