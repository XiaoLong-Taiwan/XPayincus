# v1.0.18 宿主安裝認證修復與版本同步

本版為統一產品發行目標，根 `VERSION`、Agent／ZFS VERSION、四份 package.json、RFW 三個自家 crate 與 Cargo.lock、Go Agent 預設版本、Compose 映像／建置標籤及現行版本 fixture 同步至 v1.0.18。根／面板／Agent／宿主元件文件與中英文架構及發行頁同步更新。

現行最低 updater 記載修正為 `v1.0.3`，與現行 Agent 及面板 OTA manifest 產生器一致；本輪不變更更新器邏輯。歷史發行稿、交接、版本日誌與舊版條目保留原版本及當時驗證證據，不能用來推定現行 updater 或生產部署版本。

發行契約維持完整 30 件資產及 16 筆 SHA256SUMS。保留第三方依賴、既有宿主資產釘選與實際 ZFS 模組版本；ZFS 仍為 builder 原始碼交付，Go Agent 不直接載入 eBPF 或 ZFS 核心模組。Compose 維持雙前端、單一 Node API 與 PostgreSQL 的部署邊界。

一般宿主安裝入口修復既有 Agent 認證分支不可達的問題。明確由 CLI 或面板注入的宿主安裝 Token 優先，即使已有 Agent 設定仍使用 Token 下載目前面板憑證，略過舊 Agent 的自動信任刷新與更新。未提供 Token 時，僅在既有設定檔可讀、HTTPS 面板位址及 Agent ID／密鑰格式有效時，省略 Token 輸入並沿用既有 HMAC 認證；非互動模式仍須提供 `--mode`。設定缺失或格式無效時，互動模式仍要求輸入 Token，非互動模式則在安裝確認前拒絕繼續。格式有效不代表遠端認證成功，HMAC 失敗不回退至 Token 憑證下載。

Token 路徑重複匯入相同憑證時，確認現有信任為 `client` 且 `restricted` 為 `false` 才繼續。若已有 `panel` 或 `panel-<指紋>` 信任而新憑證不同，新增目前憑證並保留舊信任；此新增步驟不自動清理舊項，須在確認新連線正常後另行審查。既有 HMAC 刷新仍在回連驗證成功後才移除舊信任。

新增完整 `main` 入口契約測試，模擬宿主系統操作，涵蓋 CLI／面板注入 Token 優先、無 Token 的有效既有設定、互動模式免 Token 輸入、設定缺失或格式無效、非互動模式必要參數及認證失敗不回退。

本輪編輯版本、安裝入口、契約測試與文件並靜態核對差異，保留工作區既有修改。未執行本機測試、型別檢查、建置或封裝，未提交、推送、建立 tag、發布、部署或 OTA，也未重新查核遠端 Release。新增測試的執行結果待對應提交的 CI 確認。

後續測試、建置、封裝與發布證據須以對應提交的 GitHub Actions、GitHub Release 及 GHCR 為準；本次版本同步不代表已發布或完成隔離真機驗收。
