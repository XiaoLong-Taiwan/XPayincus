# v1.0.11

統一產品發行準備，基於已正式發布的 v1.0.10。本稿描述本輪工作區的新增功能與交付要求；v1.0.11 尚未發布，實際資產與映像狀態以 GitHub Release、Actions 及 GHCR 為準。

## 交付與購買體驗

- 新增持久化交付工作與階段事件，記錄資源建立、啟動、提交、端口配置及通知進度；程序中斷後核實遠端資源再續作，無法確認歸屬時保留資源等待人工處理。
- 實例與訂單畫面提供交付進度及重試入口；任務中心彙整建立、實例操作與還原任務，按使用者權限呈現狀態及錯誤。
- 購買流程保存草稿，回到流程時還原選項；方案到貨訂閱依方案及地區追蹤恢復供應，以站內通知提醒，庫存仍以實際購買時為準。
- 錢包及實例相關畫面提供 7／30 天自動續費預估，顯示預計扣款、餘額缺口及首次不足時間；預估不鎖定價格或保證扣款成功。

## 節點維護與托管提款

- 新增節點維護計畫、容量／架構／儲存池與網路預檢、維護期間操作互斥、冷搬遷階段紀錄及人工接管／回復入口。
- 冷搬遷目前限相容架構及類型、相同對外 NAT 位址與已明確標記的共享 OVN 網路，且實例無 IPv6、端口映射、反向代理及外掛磁碟。搬遷會停機，來源副本保留至後續核實處理，不宣稱支援任意跨節點遷移。
- 新增管理端托管提款處理頁，記錄處理中、已付款與失敗狀態，保存付款方式、參考號／憑證與失敗原因，追蹤失敗退款以避免重複返還。

## Agent 與宿主元件

- Agent 以背景採集提供資源與實例資料，加入有容量及保留期限制的歷史 spool；面板接收確認後再移除已補送樣本，提供歷史查詢及去重。
- 面板持久保存 Agent 更新授權與操作狀態；新版 Agent 以 operation ID 記錄下載、校驗、替換及等待健康確認，重啟後以相符版本與健康階段回報。舊 Agent 維持版本確認相容流程。
- 預設宿主 state 為 `/var/lib/incudal-agent`，spool 上限 16 MiB、保留 72 小時；安裝模板配置私人目錄與 systemd StateDirectory。重裝保留原設定，自訂路徑須由管理者確保權限與持久性。
- 宿主詳情新增 RFW／ZFS 唯讀狀態；獨立工具與 timer 原子發布狀態 JSON，RFW 管理程式核對 XDP 附加狀態，ZFS 提供唯讀狀態收集。Go Agent 不載入 eBPF／ZFS 核心模組，也不隨自身升級替換宿主元件。

## 部署與發行契約

- Compose 新增唯讀 doctor、舊宿主遷移規劃、更新 preflight 與備份清單；診斷／規劃不等於完成切換或 schema 相容驗收。
- 宿主管理工具併入既有 ZFS builder source 資產，`operations.py` 納入最小 Compose bundle；不新增 Release 資產類型，維持 13 件原始檔、13 份 checksum、三份新增 JSON manifest 及 SHA256SUMS，共 30 件。
- 三份 VERSION、四份 package.json、RFW 三個自家 crate 與 Cargo.lock、Go Agent 預設版本、Compose 映像及建置標籤同步為 v1.0.11。保留第三方依賴、歷史發行紀錄、既有宿主資產釘選與最低 updater `v0.0.3`。
- Agent manifest 與面板 OTA manifest 維持各自原格式與範圍；ZFS 統一資產仍為 source-only，`kernelModulesBuilt: false`，不把產品版本當作實際 ZFS 模組版本。

## 升級要求與驗證狀態

- 本版包含 `20261110000000_add_delivery_maintenance_stock_payments` migration，新增交付工作／事件、庫存訂閱、維護計畫及提款付款欄位／狀態；須與對應前後端程式一併交付，更新前備份資料庫、設定、原加密金鑰及憑證。
- 面板維持單一 Node API 程序。面板端 Agent journal 與宿主 Agent state 均需私人且持久的可寫目錄；服務重啟、容器重建及來源切換後的持久性須於目標環境核對。
- Compose 重建與原生 Panel OTA 分別遵循根 RELEASE 契約；不提供 DB 自動回滾。歷史面板 v1.5.9 轉統一版 v1.0.x 仍需受控遷移，不自動降版。
- 2026-11-11 本次版本同步僅編輯來源與文件並靜態核對差異，依要求未執行測試、型別檢查、建置、封裝、提交、推送、tag、發布、安裝、部署或 OTA。功能執行、資料庫遷移、升級回復及目標核心／網卡／儲存相容性仍待後續 CI 與隔離真機驗收。
